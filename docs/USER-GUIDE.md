## 1. เข้าใช้งานครั้งแรก

เปิดเบราว์เซอร์ไปที่ที่อยู่ของระบบ กรอกอีเมลและรหัสผ่านที่ผู้ดูแลระบบตั้งให้

**สิ่งที่ควรรู้**

- รหัสผ่านต้องยาวอย่างน้อย **10 ตัว** และมีทั้งตัวอักษรและตัวเลข
- กรอกรหัสผิด **5 ครั้งใน 1 นาที** ระบบจะล็อกชั่วคราว รอสักครู่แล้วลองใหม่
- เปลี่ยนรหัสผ่านได้ที่เมนูมุมขวาบน → **โปรไฟล์**
- สลับภาษาไทย/อังกฤษได้ที่ปุ่มบนแถบด้านบน
- ใช้บนแท็บเล็ตในคลังได้ เมนูจะยุบเป็นปุ่มขีดสามขีดมุมซ้ายบน

**ลืมรหัสผ่าน** กดลิงก์ "ลืมรหัสผ่าน" ที่หน้าเข้าสู่ระบบ หรือแจ้งผู้ดูแลระบบตั้งให้ใหม่

> ระบบบันทึกทุกอย่างที่คุณทำ — ใครแก้อะไร เมื่อไร ค่าเดิมคืออะไร
> ห้ามใช้บัญชีของคนอื่น เพราะประวัติจะไปลงชื่อคนนั้นแทน

## 2. หน้าจอหลักและเมนู

**แดชบอร์ด** เป็นหน้าแรกหลังเข้าสู่ระบบ บอกว่ามีอะไรค้างอยู่บ้าง

| กล่อง | ความหมาย |
|---|---|
| ยอดขายเดือนนี้ / ปีนี้ | ยอดรวมของใบสั่งขายที่ยังไม่ถูกยกเลิก (รวม VAT) |
| ส่งมอบครบแล้ว | เฉพาะใบที่ส่งของครบทั้งใบ |
| Win rate | ใบเสนอราคาที่ลูกค้าตอบรับ ÷ ใบที่ลูกค้าตัดสินใจแล้ว |
| รออนุมัติ | ใบเสนอราคาที่รอผู้จัดการอนุมัติ |
| ใกล้หมดอายุ | ใบที่ยืนราคาถึงภายใน 7 วัน — ควรตามลูกค้า |
| สินค้าต่ำกว่าขั้นต่ำ | ของที่เหลือน้อยกว่าจุดสั่งซื้อ |

**เมนูด้านซ้าย** แสดงเฉพาะเมนูที่คุณมีสิทธิ์ ถ้าไม่เห็นเมนูที่ต้องใช้ แจ้งผู้ดูแลระบบ

**ทุกหน้ารายการ** ค้นหา กรอง และเรียงลำดับได้ ค่าที่ตั้งไว้ติดอยู่ใน URL —
คัดลอกลิงก์ส่งให้เพื่อนร่วมงานได้เลย เขาจะเห็นหน้าจอเดียวกับคุณ

## 3. ฝ่ายขาย — ตั้งแต่ลูกค้าถึงใบสั่งขาย

### 3.1 เพิ่มลูกค้า

**ลูกค้า → + เพิ่มลูกค้า**

| ช่อง | หมายเหตุ |
|---|---|
| รหัสลูกค้า | ห้ามซ้ำ · ใช้ค้นหาและอ้างอิงตลอดอายุงาน ตั้งให้ดีตั้งแต่แรก |
| เลขประจำตัวผู้เสียภาษี | 13 หลัก · ขึ้นบนใบเสนอราคา ตรวจให้ถูกก่อนออกใบ |
| รหัสสาขา | `00000` = สำนักงานใหญ่ (ค่าเริ่มต้น) |
| **ระดับราคา** | ตัวนี้กำหนดราคาที่ระบบดึงมาให้ตอนออกใบ — ดูตารางข้างล่าง |
| เครดิต (วัน) | ค่าเริ่มต้น 30 วัน |

**ระดับราคาสามชั้น**

- **มาตรฐาน** — ลูกค้าทั่วไป
- **ตัวแทน** — ดีลเลอร์ที่ซื้อไปขายต่อ
- **โครงการ** — งานโครงการที่ต่อรองมาแล้ว (ถูกที่สุด)

หลังบันทึกลูกค้าแล้ว เพิ่ม **ผู้ติดต่อ** และ **หน้างาน** ในหน้ารายละเอียดลูกค้า
หน้างานคือสถานที่จริงที่ไปทำงาน เช่น "DC ชั้น 3 อาคาร A" — ตอนนี้ใช้เลือกในใบเสนอราคา
และจะใช้ผูกกับงาน PM ในเฟสถัดไป

### 3.2 ออกใบเสนอราคา

**ใบเสนอราคา → + สร้างใบเสนอราคา**

1. เลือกลูกค้า → ระบบดึงผู้ติดต่อ หน้างาน และระดับราคามาให้เอง
2. กด **+ เพิ่มรายการ** แล้วพิมพ์ค้นหาสินค้าได้ทั้งรหัส ชื่อ หรือรุ่น
3. ระบบเติมราคาตามระดับราคาของลูกค้าให้ พร้อมแสดง **ยอดคงเหลือ** ข้างรายการ
4. ใส่จำนวนและส่วนลด (ใส่เป็น % หรือเป็นบาทก็ได้)
5. ดูสรุปยอดและ **margin** ที่มุมขวา
6. **Ctrl+S** บันทึก

**รายการที่ไม่ใช่สินค้าในสต็อก** เลือกประเภทเป็น *บริการ / ค่าแรง / ค่าขนส่ง / หมายเหตุ*
แล้วพิมพ์รายละเอียดกับราคาเองได้เลย เช่น "ค่าแรงติดตั้ง UPS 10kVA"

> **margin เป็นสีแดง** แปลว่ากำไรต่ำกว่า 10% — ใบจะต้องผ่านการอนุมัติก่อนส่ง

**ราคาที่บันทึกลงใบเป็นสำเนา ณ วันที่ออก** ถ้ามีคนแก้ราคาสินค้าในภายหลัง
ใบเก่าจะไม่เปลี่ยนตาม ตัวเลขที่เคยเสนอลูกค้าไปแล้วจึงตรงเสมอ

### 3.3 เส้นทางของใบเสนอราคา

```
ร่าง ──► รออนุมัติ ──► ส่งแล้ว ──┬─► ลูกค้าตอบรับ ──► สร้างใบสั่งขาย
                                  ├─► ลูกค้าปฏิเสธ
                                  └─► หมดอายุ (อัตโนมัติ)
```

**ต้องอนุมัติก่อนส่ง** เมื่อเข้าเงื่อนไขข้อใดข้อหนึ่ง (ผู้ดูแลระบบแก้ตัวเลขได้ในหน้าตั้งค่า):

- ส่วนลดรวมเกิน **15%**
- margin ต่ำกว่า **10%**
- ยอดรวมเกิน **500,000 บาท**

ถ้าไม่เข้าเงื่อนไขเลย กดส่งได้จากสถานะร่างทันที

**ใบหมดอายุอัตโนมัติ** ทุกเช้า 06:00 ระบบเปลี่ยนใบที่เลยวันยืนราคาเป็น "หมดอายุ" ให้เอง

### 3.4 แก้ใบที่ส่งไปแล้ว

**แก้ทับไม่ได้** ต้องกด **สร้างฉบับแก้ไข** ระบบจะสร้างใบใหม่ที่:

- เลขที่เดิม แต่ฉบับแก้ไขเพิ่มขึ้น 1 (`QT-202608-0007` ฉบับ 1 → ฉบับ 2)
- คัดลอกทุกรายการมาให้ แก้ได้ตามต้องการ
- ใบเดิมถูกทำเครื่องหมาย "ถูกแทนที่" และแก้ไม่ได้อีก

ไฟล์ PDF จะได้ชื่อ `QT-202608-0007_rev2.pdf` ส่งให้ลูกค้าได้โดยไม่สับสนกับฉบับเดิม

### 3.5 พิมพ์และส่ง PDF

ในหน้าใบ กด **PDF (ไทย)** หรือ **PDF (อังกฤษ)** หรือกด **ส่งอีเมล** เพื่อส่งให้ผู้ติดต่อ
พร้อมไฟล์แนบ ระบบบันทึกวันเวลาที่ส่งไว้ในประวัติของใบ

ใบมีครบตามที่ลูกค้าคาดหวัง: หัวบริษัท เลขผู้เสียภาษี ตารางรายการ VAT 7%
ยอดเป็นตัวอักษรไทย เงื่อนไขการชำระเงิน/ส่งมอบ ช่องลงนามสองฝั่ง และเลขหน้า

### 3.6 ลูกค้าตอบรับ → ใบสั่งขาย

กด **ลูกค้าตอบรับ** แล้วกด **สร้างใบสั่งขาย** (ทำได้ครั้งเดียวต่อใบ)

กรอกเลขที่ใบสั่งซื้อของลูกค้า แนบไฟล์ PO ถ้ามี แล้วเลือกคลังที่จะจ่ายของ

**ใบสั่งขายเกิดขึ้นเป็นสถานะ "รอยืนยัน" ก่อน** ยังไม่จองของ ตรวจให้เรียบร้อยแล้วกด
**ยืนยัน** ระบบจึงจองของในคลังให้

**ถ้าของไม่พอ** ระบบยังให้ยืนยันได้ แต่จะจองเท่าที่มีจริงและขึ้นเตือนว่าขาดกี่ชิ้น
(ค้างส่ง) พอของเข้าคลังแล้วค่อยเปิดใบส่งของเพิ่ม

**ยกเลิกใบสั่งขาย** ระบบคืนของที่จองไว้ให้อัตโนมัติ

## 4. ผู้จัดการฝ่ายขาย — การอนุมัติ

ใบที่รออนุมัติขึ้นบนแดชบอร์ด กดเข้าไปดูได้ทันที

ในหน้าใบจะเห็น **เหตุผลที่ต้องอนุมัติ** ระบุชัดว่าติดเงื่อนไขข้อไหน พร้อม margin
รายบรรทัดและของทั้งใบ

- **อนุมัติ** → ใบพร้อมให้ฝ่ายขายส่งลูกค้า
- **ส่งกลับแก้** → ใบกลับไปเป็นร่าง ฝ่ายขายแก้แล้วส่งมาใหม่ได้

> **อนุมัติใบของตัวเองไม่ได้** ถ้าคุณเป็นคนออกใบนั้นเอง ต้องให้ผู้จัดการอีกคน
> หรือผู้ดูแลระบบอนุมัติแทน

ผู้จัดการเห็นใบของฝ่ายขายทุกคน ส่วนพนักงานขายเห็นเฉพาะใบของตัวเอง

## 5. คลังสินค้า — รับ โอน ปรับปรุง ส่งของ

### หลักการที่ต้องเข้าใจก่อน

ยอดคงเหลือของทุกสินค้า **มาจากผลรวมของรายการเคลื่อนไหวเสมอ** ระบบไม่มีทางให้ใครแก้
ยอดคงเหลือตรง ๆ ทุกการเปลี่ยนต้องผ่านเอกสาร และเอกสารที่ post แล้วแก้ไม่ได้

**ยอดสามตัวที่ต้องแยกให้ออก**

| ยอด | หมายถึง |
|---|---|
| คงเหลือ | ของที่อยู่ในคลังจริง |
| จองไว้ | ถูกใบสั่งขายจองไว้แล้ว แต่ยังไม่ได้ยกออก |
| **ว่าง** | คงเหลือ − จองไว้ = ของที่เอาไปขายได้จริง |

### 5.1 รับสินค้าเข้าคลัง

**ใบรับสินค้า → + สร้าง** เลือกคลัง ผู้ขาย เลขที่ใบส่งของของผู้ขาย
ใส่รายการพร้อมจำนวนและราคาทุนต่อหน่วย

สินค้าที่ต้องคุม serial ให้กรอกหมายเลขให้ครบตามจำนวน

ตรวจแล้วกด **บันทึกเข้าสต็อก** — **หลังจากนี้แก้ไม่ได้** ถ้ากรอกผิดต้องเปิดใบปรับปรุงแก้

### 5.2 โอนของระหว่างคลัง

**ใบโอนคลัง → + สร้าง** เลือกคลังต้นทางและปลายทาง (`HQ` สำนักงานใหญ่ ·
`VAN` สต็อกรถบริการ · `CONSIGN` สต็อกฝากหน้างานลูกค้า)

ระบบตรวจให้ว่าคลังต้นทางมีของพอไหม ถ้าไม่พอจะไม่ยอมให้ post

### 5.3 ปรับปรุงสต็อก (นับสต็อก)

**ใบปรับปรุงสต็อก → + สร้าง** เลือกเหตุผล — นับสต็อก / ชำรุด / สูญหาย / พบเพิ่ม /
ยอดยกมา — แล้วใส่ **จำนวนที่นับได้จริง**

ระบบเทียบกับยอดในระบบและคำนวณผลต่างให้เอง ไม่ต้องคิดเอง

ใบปรับปรุงเป็นทางเดียวที่แก้ยอดคงเหลือได้ และทุกใบมีชื่อคนทำกับเหตุผลติดอยู่ตลอดไป

### 5.4 ส่งของตามใบสั่งขาย

**ใบสั่งขาย → เปิดใบที่ยืนยันแล้ว → สร้างใบส่งของ**

1. ระบบแสดงรายการที่ยังค้างส่ง พร้อมจำนวนที่ส่งได้
2. แก้จำนวนได้ถ้าส่งไม่ครบรอบเดียว (ทยอยส่งได้)
3. **สินค้าที่คุม serial ต้องเลือกหมายเลขให้ครบตามจำนวน** ระบบให้เลือกเฉพาะตัวที่อยู่ในคลัง
4. กรอกชื่อผู้รับและหมายเหตุรถ
5. กด **บันทึกส่งของ**

**ตอน post ระบบทำให้อัตโนมัติ**

- ตัดของออกจากคลังและปลดของที่จองไว้
- เปลี่ยนสถานะ serial เป็น "ขายแล้ว" พร้อม**เริ่มนับประกันจากวันส่ง**
- อัปเดตสถานะใบสั่งขายเป็น "ส่งบางส่วน" หรือ "ส่งครบแล้ว"

> ตรวจ serial ให้ตรงกับของที่ยกขึ้นรถจริง เพราะเลขนี้จะตามไปถึงงานเคลมประกันและงาน PM

### 5.5 ของใกล้หมด

สินค้าที่ยอดว่างต่ำกว่าขั้นต่ำขึ้นบนแดชบอร์ดและมีป้ายเตือนในหน้ารายการ
ตั้งขั้นต่ำและจำนวนสั่งซื้อได้ที่หน้าสินค้าแต่ละตัว

## 6. รายงานและไฟล์ Excel

**รายงาน** — เลือกช่วงวันที่เอง หรือกดปุ่มลัด เดือนนี้ / เดือนที่แล้ว / ปีนี้

มีกราฟยอดขาย 6 เดือนย้อนหลัง อันดับลูกค้า อันดับสินค้าขายดี และมูลค่าสต็อกคงคลัง

**ไฟล์ Excel สามชุด** (ภาษาไทยครบ เปิดใน Excel ได้ทันที)

| ไฟล์ | เนื้อหา |
|---|---|
| สินค้าและสต็อก | หนึ่งบรรทัดต่อคู่สินค้า–คลัง พร้อมยอดคงเหลือ จอง ว่าง และมูลค่า |
| รายงานใบเสนอราคา | ทุกใบในช่วงวันที่ พร้อมสถานะและยอดเงิน |
| ประวัติการเคลื่อนไหวสต็อก | ทุกรายการเรียงจากเก่าไปใหม่ ยอดคงเหลือต่อกันเป็นลูกโซ่ |

> ฝ่ายขายจะได้เฉพาะใบของตัวเองในไฟล์ ตรงกับที่เห็นบนหน้าจอ
> ส่วนวิศวกรและผู้ดูอย่างเดียวดูรายงานได้แต่ดาวน์โหลดไฟล์ไม่ได้

**ไฟล์ที่ดาวน์โหลดไปแล้วระบบตามต่อไม่ได้** เก็บให้ดี อย่าส่งต่อออกนอกองค์กร

## 7. ผู้ดูแลระบบ

### 7.1 ผู้ใช้และสิทธิ์

**ตั้งค่า → ผู้ใช้งาน** เพิ่มพนักงาน กำหนดบทบาท และปิดใช้งานบัญชีคนที่ลาออก

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้ดูแลระบบ | ทุกอย่าง รวมงานตาม PDPA และดูประวัติการใช้งาน |
| ผู้จัดการฝ่ายขาย | งานขายทั้งหมด + อนุมัติใบ + ดูประวัติการใช้งาน |
| ฝ่ายขาย | ลูกค้า ใบเสนอราคา ใบสั่งขาย (เฉพาะของตัวเอง) ดูสต็อกได้ |
| คลังสินค้า | สินค้า ผู้ขาย งานคลังทั้งหมด ใบส่งของ |
| วิศวกร | ดูสินค้า สต็อก และรายงาน |
| ผู้ดูอย่างเดียว | ดูอย่างเดียว ดาวน์โหลดไฟล์ไม่ได้ |

**ปิดใช้งานดีกว่าลบ** — บัญชีที่ปิดเข้าระบบไม่ได้ทันที แต่ประวัติงานที่เคยทำยังอยู่ครบ

### 7.2 ตั้งค่าระบบ

**ตั้งค่า → ตั้งค่าระบบ**

- **ข้อมูลบริษัท** ชื่อ ที่อยู่ เลขผู้เสียภาษี โลโก้ ลายเซ็น — ขึ้นบนใบเสนอราคา
- **เอกสาร** อัตรา VAT จำนวนวันยืนราคา เงื่อนไขการชำระเงิน/ส่งมอบเริ่มต้น
- **เกณฑ์อนุมัติ** เปอร์เซ็นต์ส่วนลด margin ขั้นต่ำ และยอดที่ต้องอนุมัติ

เปลี่ยนแล้วมีผลกับใบที่ตัดสินหลังจากนั้นทันที ใบเก่าไม่กระทบ

### 7.3 ประวัติการใช้งาน

**ตั้งค่า → ประวัติการใช้งาน** ดูได้ว่าใครทำอะไรเมื่อไร พร้อม **ค่าก่อนและหลัง**
ทุกฟิลด์ที่เปลี่ยน กรองได้ตามคน ตามประเภทข้อมูล และตามช่วงเวลา

หน้านี้อ่านอย่างเดียว ไม่มีทางแก้หรือลบประวัติผ่านระบบ

### 7.4 คำขอตาม PDPA

ข้อมูลผู้ติดต่อลูกค้าเป็นข้อมูลส่วนบุคคลตามกฎหมาย เมื่อลูกค้าใช้สิทธิ์ ให้ทำที่
**ลูกค้า → เปิดรายที่ต้องการ → ข้อมูลส่วนบุคคล**

**ลูกค้าขอดู/ขอสำเนาข้อมูล** กด **ดาวน์โหลดสำเนา (JSON)** แล้วส่งไฟล์ให้ลูกค้า
ไฟล์มีทุกอย่างที่ระบบเก็บไว้ รวมประวัติว่าใครเข้าถึงข้อมูลนี้บ้าง

**ลูกค้าขอให้ลบข้อมูล** กรอกเหตุผลและพิมพ์รหัสลูกค้ายืนยัน แล้วกดลบ

- ลูกค้าที่ **ยังไม่เคยมีใบเสนอราคาหรือใบสั่งขาย** → ลบออกจากระบบทั้งหมด
- ลูกค้าที่ **เคยมีเอกสารแล้ว** → ระบบลบชื่อ เลขผู้เสียภาษี ที่อยู่ เบอร์ อีเมล
  และผู้ติดต่อทั้งหมดทิ้ง แต่เก็บตัวเลขในเอกสารไว้ เพราะ**กฎหมายภาษีบังคับให้เก็บ
  เอกสารไว้ 5 ปี** ชื่อในใบเก่าจะกลายเป็น `[ลบตามคำขอ PDPA]`

> **ทำแล้วย้อนกลับไม่ได้ และกู้คืนไม่ได้** ตรวจให้แน่ใจว่าเป็นคำขอจริงจาก
> เจ้าของข้อมูลก่อนกด

**ลบผิดคน?** ถ้าเป็นการลบธรรมดา (เมนูลบในหน้าลูกค้า) ยังกู้ได้ —
ติ๊ก "ที่ถูกลบแล้ว" ในหน้ารายการลูกค้าเพื่อค้นหา แล้วกดกู้คืน
แต่ถ้าเป็นการลบตามคำขอ PDPA แล้ว กู้ไม่ได้

php artisan texson:security-check --production

คำสั่งนี้ตรวจ 14 ข้อของ checklist ความปลอดภัยกับเครื่องที่รันจริง

## 8. คำถามที่เจอบ่อย

**แก้ใบเสนอราคาที่ส่งไปแล้วได้ไหม**
แก้ทับไม่ได้ ต้องกดสร้างฉบับแก้ไข ใบเดิมจะถูกเก็บเป็นประวัติ วิธีนี้ทำให้ตรวจย้อนหลังได้ว่า
เคยเสนอลูกค้าไปเท่าไร

**ยกเลิกใบส่งของที่ post ไปแล้ว**
ทำไม่ได้ ของถูกตัดออกจากคลังจริงไปแล้ว ถ้าของถูกส่งคืน ให้เปิดใบปรับปรุงสต็อก
เลือกเหตุผล "พบเพิ่ม" พร้อมหมายเหตุอ้างเลขที่ใบส่งของ

**ยอดคงเหลือไม่ตรงกับของจริงในคลัง**
เปิดใบปรับปรุงสต็อก เลือกเหตุผล "นับสต็อก" แล้วใส่จำนวนที่นับได้จริง
ระบบคำนวณผลต่างและบันทึกให้เอง

**ทำไมกดส่งใบเสนอราคาไม่ได้**
ใบติดเงื่อนไขที่ต้องอนุมัติ ในหน้าใบจะบอกว่าติดข้อไหน แจ้งผู้จัดการอนุมัติก่อน

**ทำไมยืนยันใบสั่งขายแล้วจองของไม่ครบ**
ของว่างในคลังมีไม่พอ ระบบจองเท่าที่มีและบันทึกส่วนที่ขาดเป็นค้างส่ง
พอของเข้ามาแล้วเปิดใบส่งของเพิ่มได้

**หาเมนูที่ต้องใช้ไม่เจอ**
เมนูขึ้นตามสิทธิ์ของบทบาท แจ้งผู้ดูแลระบบตรวจสอบสิทธิ์ให้

**ภาษาไทยใน PDF เพี้ยน**
ไม่ควรเกิด ระบบใช้ฟอนต์ Sarabun ที่รองรับสระบน–ล่างครบ ถ้าเจอให้แจ้งพร้อมไฟล์ตัวอย่าง

**คลิกลิงก์จากอีเมลแล้วเด้งไปหน้าเข้าสู่ระบบทุกครั้ง**
เป็นค่าความปลอดภัยที่ตั้งใจตั้งไว้ เข้าสู่ระบบแล้วระบบจะพากลับไปหน้าที่ต้องการเอง

## 9. ศัพท์ที่ใช้ในระบบ

| คำ | ความหมาย |
|---|---|
| SKU | รหัสสินค้าที่ไม่ซ้ำกัน ใช้ค้นหาและอ้างอิง |

| ระดับราคา | มาตรฐาน / ตัวแทน / โครงการ — กำหนดที่ลูกค้าแต่ละราย |

| ค้างส่ง | ส่วนที่ลูกค้าสั่งแล้วแต่ของยังไม่พอส่ง |

| ฉบับแก้ไข | ใบเสนอราคาเวอร์ชันใหม่ที่ออกแทนใบเดิม |
| ถูกแทนที่ | ใบเก่าที่มีฉบับแก้ไขใหม่ออกมาแล้ว |
